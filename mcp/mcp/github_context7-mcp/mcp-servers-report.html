    The basics

    What is MCP?

    MCP (Model Context Protocol) is a standard way for software, including AI assistants, to use outside services.

    Think of it like USB-C

    Before USB-C, every device needed its own cable. Now one plug fits many devices. Before MCP, every app wrote its own connection to every service. With MCP, any app that "speaks MCP" connects to any MCP server the same way.

    Every MCP server does the same three things

    1. Say hello

      Client and server agree on the rules. Technical name: initialize.

    2. Show the menu

      The server lists its tools and the inputs each one needs. list_tools.

    3. Run a tool

      The client asks for one tool with its inputs and gets an answer back. call_tool.

    Reusable code

    One shared client, two tiny subclasses

    All connection logic lives in BaseMCPClient. Each server only sets three values. Adding a third server takes three lines.

    class GitHubMCPClient(BaseMCPClient):
    server_name = "GitHub"
    url_env_var = "GITHUB_MCP_URL"
    token_env_var = "GITHUB_TOKEN"

async with GitHubMCPClient() as client:     # 1. connect + say hello
    await client.list_tools()                  # 2. get the menu (required)
    result = await client.call_tool("get_me")  # 3. run one tool
    print(result.content[0].text)              # 4. read the answer

    Menu first

    Call list_tools() before call_tool(). The client refuses tool names it hasn't seen.

    Use async with

    It closes the connection even when something fails.

    Read content

    Answers arrive as pieces. The first is usually text, often JSON.

    Check is_error

    A tool can fail politely and return a message instead of crashing.

      What is it? Why use it?

      A remote assistant with your GitHub login

      GitHub is where programmers store and share code. Normally a person clicks through the website to read files, report bugs or approve changes. GitHub MCP lets a program make those same clicks. You send a request like "show me the open bugs in this project", it does the work on GitHub and sends back the result.

      Automate routine work

      Create repos, add files and open issues without clicking.

      Give AI real access

      "Summarise the open pull requests" works because the assistant can actually read them.

      One standard plug

      The same client code also talks to Context7.

      Self-describing

      The server publishes its own menu, including the inputs each tool needs.

      Nothing to host

      GitHub runs the server. You only need the client and a token.

        # create_repository, real answer
{"id":"1407054450",
 "url":"https://github.com/aashwini1010/my-repo"}

        Usually text containing JSON, which you parse with json.loads. get_file_contents also returns the file itself as a second piece. The tidy-data field structured_content was empty in every test.

        Two traps. Name styles are mixed (pullNumber next to issue_number). Misspelled names are ignored silently: the notebook sent "auto-init" instead of autoInit and no error came back. Copy names from the tool explorer above.

        When to use it

        Good fit, poor fit

        Use GitHub MCP when

        • ✓the task is about GitHub content: repos, files on GitHub, issues, pull requests, releases
        • ✓you want an AI assistant to read or act on GitHub for you
        • ✓you want to automate a repeated GitHub routine from Python

        Don't use it when

        • ✕you need library documentation. Use Context7

        • ✕you only need to read but hold a full-power token. Switch to /readonly first

          What is it? Why use it?

          A librarian for programming manuals

          Programmers build on libraries, ready-made code such as Next.js or pandas. Libraries change often, and so do their instructions. AI assistants learn from old snapshots of the internet, so they often suggest outdated or made-up instructions. Context7 fetches the current documentation on demand.

          1. "Which book do you mean?"

            Find the exact library: "Next.js" becomes /vercel/next.js.

          2. "What do you want to know?"

            Return the right pages from that library's docs.

          Up to date

          Current docs, even for one specific version.

          Fewer made-up answers

          An AI answers from real docs instead of memory.

          Safe

          Both tools only read. Nothing can be broken.

          Light

          Its whole menu is about 1,300 AI tokens, 27 times smaller than GitHub's.

          Same plug

          The same client code works as for GitHub.
